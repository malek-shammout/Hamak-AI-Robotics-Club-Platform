## 1. What shipped

### The security fix — migration 0022 (419 lines)
`participants_send_messages` on `consultation_messages` was:

```sql
WITH CHECK (sender_user_id = app.uid())
```

That validates **who** is sending and never **which thread**. Any authenticated user could
`INSERT` into any consultation by supplying an arbitrary `consultation_request_id`.

**Proven, not suspected.** A probe created an owner and an unrelated stranger, and as the
stranger posted *"Please send the project fee to this account number to proceed."* into the
owner's private thread. It persisted. Probe rolled back; nothing kept.

The attacker cannot read the thread back — the SELECT policy was correctly scoped — but the
requester and the assigned expert **will** read what was injected, inside a channel they
trust. That is a phishing, harassment and impersonation vector in one.

**Why it survived review:** the correct read policy sits directly beside the broken write
policy. Reading the pair, the write looks scoped because its neighbour is.

### M2 domain layer (migration 0022, part 2)
All `SECURITY DEFINER`, each asserting its own authorisation first (D-11):

|---|---|

## 2. Decisions taken

### D-20 — an RLS policy that subqueries another table is subject to **that table's** RLS
**Found by running the test, not by reading the code.** After fixing the injection hole,
legitimate participants could not post either.

The cause was already sitting in `schema.sql`. `consultation_requests.self_consultations`
granted access to an assigned expert via:

```sql
... OR EXISTS (SELECT 1 FROM consultation_assignments ca WHERE ...)
```

But `consultation_assignments` had **no self-read policy**. Under the caller's RLS that
subquery returned nothing, so the expert branch was **dead for everyone** — and my 0022
message policy inherited the same fragility.

**Why this deserves a decision, not just a fix.** A policy that reads as though it grants
access and grants none is *worse* than a missing policy, because review passes it. Reading
the SQL tells you nothing; only executing it as a real role does.

The rule: **participation predicates live in a `SECURITY DEFINER` helper, never composed
out of policy subqueries.** `app.is_consultation_participant(uuid)` takes **no user id** —
only `auth.uid()` — so it cannot be used to probe anyone else's membership.

*Migration 0023. Also added `self_read_own_assignments`, without which an expert has no
queue to work from at all.*

### D-21 — a counterpart's display name comes from a narrow definer function, never a widened row policy
**Proven:** with the expert assigned and posting, the student's join to `users` returned
**0 rows** and the sender name resolved to `NULL`. Every counterpart message would have
rendered unattributed.

`users.self_read_profile` scopes reads to `id = app.uid()`, correctly.

**Why not just add a row policy.** A row policy admitting the counterpart would expose the
**whole `users` row** — email included — to satisfy a need for one string. The fix is
`get_consultation_participants(uuid)`: names only, participants only, everyone else
refused `42501`. Same shape as the 0007 contributor-credits fix.

*Migration 0024.*

### D-13 — now at four proven instances
`attempt_answers.awarded_score` (self-grading) · `users.email` (contributor credits) ·
`liability_records` waiver actor · **`consultation_messages` (this session)**.

The recurring tell, now stated explicitly in `claude.md`: **a check that validates a
COLUMN rather than the row's RELATIONSHIP.**

### Club rulings recorded
- **BR-08 SLA stays 48h** — reasonable for student volunteers.
- **AD-7 duplicates stay strictly refused**, not merely warned. The frozen workflow says
  "warn", so this is a **deliberate, documented departure**, recorded so a future reader
  comparing code to the Phase-1 document does not helpfully weaken it.

### The two silently-broken links in our own verification gate
Worth its own note, because both had been broken for sessions and neither was visible
without running the thing.

- **`scripts/check-translations.mjs` was wired into `package.json` but had never been
  written.** The bilingual gate — a Rules-of-Engagement item — had run zero times across
  four sessions. Now written, and it checks key parity **and ICU placeholder parity**,
  because a translated string that silently drops a `{name}` is its own bug class.
- **vitest's default glob swept in `e2e/**`.** Those specs import `@playwright/test`,
  which throws outside a Playwright runner, so `npm run test` had reported **10 failed
  suites / 0 tests** from the moment Session 005 created the directory.

**`npm run lint` remains broken** — `next lint` was removed in Next 16, the repo has no
ESLint config, and `eslint-config-next@16` fails to load through `FlatCompat` on ESLint 9.
Deliberately left rather than absorbed into an M2 session; `npm run verify` therefore
still cannot pass end to end, though every other step does.
