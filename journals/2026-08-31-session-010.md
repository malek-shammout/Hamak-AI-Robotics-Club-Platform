# Session 010 — RBAC route validation and auth E2E stability

## Objective

Validate the real staff-identity matrix across multiple roles and stabilize the Playwright RBAC checks so they reflect actual permission coverage rather than a flaky timeout window.

The work covered:

1. exercising role-bearing staff identities for `PROJECTS`, `TRAINING`, `LOGISTICS`, and `ADMIN`;
2. validating route access across the staff surface; and
3. fixing the intermittent Chromium timeout caused by slow staff-page loads during route-coverage assertions.

## Implemented solution

- Tightened the RBAC suite to assert the real route surface for each role while allowing the page to finish rendering before the assertions start.
- Added `test.slow()` and a longer `expect.poll()`/`main` wait window so staff pages with heavier data loads no longer fail on the default Playwright timeout.
- Re-ran the live staff route checks against the real Supabase identities created for the project.
- Updated the project memory to record the role-validation result and the fix path.

## Findings

- The intermittent failure was not a permission model defect; it was a timing problem in the RBAC route spec.
- Staff pages can take longer than the default 30s assertion window in Chromium when the page is still resolving data and redirect logic.
- Extending the wait budget and waiting on the final rendered `main` content fixed the false-negative without weakening the checks.
- The project’s actual RBAC model allows the department roles to reach the expected staff surfaces when the role membership is valid, so the test should assert the real authorised route matrix rather than a narrower “one role, one module” assumption.
