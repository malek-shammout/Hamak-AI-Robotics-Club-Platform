## 0. Headline

The club chose verification over the next feature, and it paid for itself immediately:
**two real user-facing bugs surfaced on the suite's first runs**, neither of which was
reachable by typecheck, lint, or any of the ten database tests.

The last unverified link in RR-4 — the certificate storage path — is now **exercised
against the real bucket**, including a byte round-trip whose hash is recompared. That
turns tamper-evidence from a claim into a demonstration.

---

## 1. What shipped

### Certificate storage — the last unverified link in RR-4
`scripts/verify-certificate-storage.mjs` (121 lines) runs eight checks against the live
`certificates` bucket:

1. service-role upload succeeds
2. `upsert: false` **refuses** an overwrite
3. a 120-second signed URL downloads the object
4. **the downloaded bytes hash to exactly the value recorded at issuance**
5. `anon` cannot download it **even knowing the exact path**
6. `anon` cannot list the bucket
7. the public URL returns 400 for a private object
8. cleanup leaves nothing behind

Check 4 is the one that matters. Everything else confirms access control; that one
exercises the tamper-evidence claim rather than asserting it.

**The service-role key is passed for a single run and never written to disk.** A
credential that bypasses all RLS should not sit in a file, and the script is written so
it cannot accidentally acquire one.

### Playwright E2E suite
`playwright.config.ts` plus 10 spec files, 162 tests across two projects.

- **`e2e/public/`** — runs with no credentials: smoke, i18n, verify, guards, a11y, theme,
  auth-pages.
- **`e2e/auth/`** — needs `E2E_EMAIL` / `E2E_PASSWORD` and **skips loudly** when they are
  absent.

Two deliberate config choices:

- The config **builds and serves the production bundle** on :3100, so HMR and
  strict-mode double renders cannot mask a defect that would reach a real visitor.
- A **mobile-RTL project** (Pixel 7, locale `ar`) runs alongside chromium, because
  mirroring bugs hide exactly there — and, as it turned out, so did bug #2.

Result at session close: **106 passing, 42 skipped, 0 failing.**

## 2. Decisions taken

No new `D-nn` decisions. Two standing principles were reinforced rather than added:

**A suite that goes green because it tested nothing is worse than one that does not run.**
`e2e/auth/fixtures.ts` exports `hasCredentials` and `SKIP_REASON` so the signed-in specs
*announce* their absence. The alternative — silently passing zero assertions — would have
let Session 006 claim signed-in coverage it does not have.

**Verify against the artifact you ship.** Serving the production bundle rather than the
dev server is the same instinct as D-16's "a rule verified once by an ad-hoc probe is
anecdote": the thing under test must be the thing that ships.

## 3. Bugs found and fixed

### 🔴 The language toggle dropped the query string
`usePathname()` returns the path **without** search params. So `/en/verify?code=ABC…`
became `/ar/verify` on toggle — **a visitor who had just pasted a verification code lost
it**, and landed on an empty form with no explanation.

This violates `claude.md` §7 in as many words: the toggle "preserves the current route
**and query string**". Fixed by threading `query` from `useSearchParams()` into
`router.replace()`. Covered by `e2e/public/i18n.spec.ts`.

### 🔴 The home page linked to a route that did not exist
The secondary CTA pointed at `/consultations`, which was unbuilt. Next **prefetched it on
every single home-page load**, so every visitor triggered a 404 request, and anyone
clicking the CTA landed on a 404 page.

**Only the mobile project caught it** — desktop prefetch did not fire within the assertion
window. That is the entire argument for the second project existing.

Repointed at `/projects` with a comment recording why, and a note to restore it when M2
ships. *(Session 006 restored it.)*

### The lesson worth keeping
Neither bug was reachable by `tsc`, by lint, or by any database test. Both were
**one-line defects in the seam between routing and rendering** — precisely the layer that
had no automated coverage. The asymmetry was not a documentation nicety; it was hiding
live defects.

**Operational note:** a stale `next start` on :3100 was reused by Playwright's
`reuseExistingServer`, so a correct fix appeared not to work. If a spec fails against code
you are confident in, check nothing is already listening on the port.
