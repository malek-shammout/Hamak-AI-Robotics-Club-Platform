## 2. Decisions taken

### D-18 — Separation of duties on requisitions, enforced on IDENTITY
The club ruled: A4 raises, A3 approves, because Logistics holds the truth of physical
stock.

**Reasoning for the strict form.** A role-based reading ("only A3 may approve") has a
hole: an **ADMIN holds every permission**, so they could raise *and* approve their own
request — precisely the person the control exists to catch. So `approve_requisition` and
`reject_requisition` refuse when reviewer = requester **for everyone**, and test 09
asserts the admin case explicitly.

The other half of the asymmetry matters as much: **raising requires no M5 permission at
all**, only ownership of the context (project membership). A team lead with zero
logistics rights may ask; only Logistics may decide. That asymmetry *is* the separation.

### D-19 — `media_assets.content_hash` added; entity count unchanged
Part D.3 names RR-4's mitigation as "versioned bucket + content hash stored on
media_assets". The column did not exist because the ERD in Part C predates the
mitigation.

**Reasoning.** This is an *anticipated* addition, not an invention — but Rules of
Engagement #1 requires any column addition recorded regardless, so it is logged here.
**Entity count is unchanged at 78 tables**; two columns were added to an existing one.

## 3. RR-1 closed — the BULK stock race

Seat allocation and serialized custody were already guarded (cohort row locks,
`uq_checkout_active_unit`). **BULK stock was not.** Nothing reserved it, so two
approvals could promise the same wire twice.

`approve_requisition` now locks the `bulk_stock` row `FOR UPDATE` and **re-reads
availability inside the lock**. Reading availability first and locking second is
precisely the race this closes; `ck_bulk_stock_nonneg` is the backstop, the lock is the
mechanism.

Two follow-on pieces were needed for correctness, not polish:
- **Consumption.** `issue_checkout` draws the hold down, decrementing `quantity_on_hand`
  and `quantity_reserved` together. Without it `quantity_reserved` climbs forever and
  the shelf empties on paper while the items sit on it.
- **Expiry.** `release_expired_reservations()` returns holds that were never collected,
  scheduled hourly.

Test 09 proves the race: 10 units on hand, one approval for 8 succeeds, a second
approval for 8 → `INSUFFICIENT_STOCK`, a cut-back approval of the remaining 2 succeeds.

**Side effect worth noting:** this also made **BR-12's team/event branch reachable**.
`issue_checkout` had supported it since migration 0017, but nothing could produce an
approved requisition, so it was DB-tested only and unusable.

## 4. RR-4 closed — four independent locks

| # | Lock | Where |
|---|---|---|
| 1 | The `certificates` bucket has **no client storage policy at all** | migration 0002 |
| 2 | `content_hash` — SHA-256 over the **exact bytes uploaded** | migration 0021 |
| 3 | **Write-once** — key/hash frozen once an asset backs a certificate; delete blocked | migration 0021 |
| 4 | `upsert: false` — storage itself refuses an overwrite | `issue-document.ts` |

Delivery is a **120-second signed URL**, minted per request behind an RLS check and
returned as a **302** so the link never lands in the page, browser history, or a
referrer header. A signed URL is a bearer capability; the window is minutes, not days.

The hash is taken over the bytes **before** upload, not re-derived from what storage
returns. Hashing what you actually stored is the whole point of tamper evidence.

### The renderer is Chromium, deliberately
`pdf-lib` and `@react-pdf/renderer` do neither bidirectional reordering nor Arabic
contextual shaping — the same letter takes a different form initial, medial, final or
isolated, and neither library implements it. Arabic comes out as **disconnected letters
in reverse**. Chromium's text stack does both correctly, so the renderer is a browser.

**This was verified visually, not assumed.** The real template was rendered and
inspected: glyphs connect, the shadda on the sample name survives, RTL layout embeds
Latin text correctly.

Madani is inlined as a **data URI** so the document renders identically offline and in
five years. A certificate that depends on a network font is a certificate that renders
differently later.

## 5. Two blockers on the push, and how they were resolved

**403 — wrong identity.** The first push reached GitHub and was rejected: this machine's
stored credential authenticated as `Microbots-Brabus`, which has no write access. Not
something tooling should fix — credentials are the club's to hold. Reported and waited.

**Non-fast-forward — unrelated histories.** After the credential fix, the push was
rejected again: the repo had been created with a README, giving it a root commit with
**no shared ancestor**.

The obvious shortcut, `git push --force`, would have **deleted that commit**. Instead:
1. Inspected first — one remote commit, `0b4358c`, containing only `README.md`.
2. Recorded the pre-merge HEAD (`b2b578b`) as a recovery point.
3. Tried a rebase; the auto-mode classifier blocked it, correctly, since rebasing
   rewrites all ten commit hashes.
4. Used `git merge --allow-unrelated-histories`, which keeps the README, preserves all
   ten commits **and their hashes**, and destroys nothing.

Cost: one merge commit in the graph. That is the right trade when the alternative is
discarding someone else's work.
