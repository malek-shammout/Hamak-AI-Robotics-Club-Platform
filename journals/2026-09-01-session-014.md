# Session 014 — launch cleanup and readiness polish

## Objective

Remove temporary demo/E2E data from the live Supabase project without touching legitimate records, document all required environment variables for future developers, and close the RBAC and authoring implementation phases at 100%.

## Implemented solution

- Added `scripts/cleanup-e2e-data.mjs`, exposed as `npm run cleanup:e2e`.
- The cleanup command is dry-run by default and requires `--execute` for mutations.
- Its scope is restricted to:
  - the exact four reserved demo seed email addresses;
  - `DEMO-*` projects;
  - `D2P-PROJECT-*`, `D2P-EVENT-*`, `D2P-ARTICLE-*`;
  - `EDITORIAL-PROJECT-*`, `EDITORIAL-EVENT-*`, `EDITORIAL-ARTICLE-*`.
- The script refuses to remove demo identities with consultation requests, cleans dependent expertise/assignment rows, handles orphaned public seed profiles safely, and verifies that all marked rows are gone.
- Updated `.env.example` with Supabase management access and shared/role-specific Playwright credential placeholders.
- Updated `claude.md` to mark M10 RBAC and M7/M8/M9 authoring as 100% complete and to record launch cleanup status.

## Live cleanup result

Dry run reported:

- 3 `DEMO-*` projects
- 0 temporary E2E events
- 0 temporary E2E articles
- 4 exact seeded demo profiles
- 0 demo consultation dependencies

The first execute attempt exposed four orphaned public seed profiles whose auth identities were already absent. The script was hardened to handle that existing inconsistency safely. The retry completed successfully:

- all 3 marked projects removed;
- all 4 exact orphaned seed profiles removed;
- no marked projects, events, articles, or seed profiles remained;
- role-bearing accounts, technologies, expertise domains, and unrelated live data were not targeted.
