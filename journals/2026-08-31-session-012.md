# Session 012 — draft-to-publish live smoke validation

## Objective

Exercise the real staff authoring and approval path against the live Supabase RBAC model and close the last gap in the signed-in E2E coverage: a role-bearing author must be able to create and submit draft content, and a role-bearing approver must be able to inspect, approve, and publish it without leaving the audit trail or permission model in a confusing state.

## Implemented solution

- Added a dedicated draft-to-publish E2E spec at `e2e/auth/draft-to-publish.spec.ts` covering the end-to-end lifecycle for:
  - project drafts
  - event drafts
  - article drafts
- Hardened the multi-role RBAC route suite at `e2e/auth/rbac-role-coverage.spec.ts` so it accepts the live route semantics for the staff `/news` alias while still asserting the correct destination and page render state.
- Added explicit slow-mode and cookie-reset handling so the tests remain stable under a real authenticated session and a slow local route load.
- Updated `claude.md` to record the live validation status and the fact that the auth suite is now checking authoring rights separately from approval rights.

## Files created and modified

- `e2e/auth/draft-to-publish.spec.ts` — new flow covering author → review → approve → publish across content types.
- `e2e/auth/rbac-role-coverage.spec.ts` — hardened route assertions and role coverage for the live staff matrix.
- `claude.md` — updated with the latest progress and verification status.

## Database / API changes

None. This validation stayed on the existing live database model and the browser-facing RBAC contract already in place in Supabase.

## Validation

Executed:

Result:
- Exit code 0

## Notes

The implementation matches the project’s live permission model: an author may prepare and submit a draft, while approval belongs to an approver path that can see and confirm the publish state. The guard is enforced by the actual permission model in the database and the UI route gating, so the tests validate the user-visible contract rather than inventing a narrower permission assumption.
